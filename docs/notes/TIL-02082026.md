# TIL (02-08-2026)

- Handle allocation and reallocation failures explicitly. Never assume they succeed.
- Use a temporary pointer with `realloc`. Only update the original pointer after success.
- Don't modify a data structure's state (`size`, `capacity`, etc.) until operations that can fail have succeeded.
- Only call `realloc` when a resize is actually needed.
- After `free`, set the pointer to `NULL` to avoid dangling pointers.
- Prefer allocating eveything on the stack unless it genuinely needs dynamic lifetime.
- Think in terms of invariants:
  - `0 <= size <= capacity`
  - `data` points to a valid allocation (or `NULL` if that's an allowed state).
  - After every operation, the program should still satisfy these invariants.

> An invariant is simply a condition that must always be true for a data structure or program to be considered valid.
